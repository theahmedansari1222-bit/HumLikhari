# Hum Likhari — ٹیسٹ منصوبہ (v1.0.0-rc.1)

## A. خودکار — ابھی چلائیں

```bash
npm test            # static ویلیڈیشن + Node ٹیسٹ (11)
npm run test:e2e    # Playwright + Chromium: frontend 21 اور admin 17 منظرنامے
```
- `scripts/validate.mjs`: syntax/JSON، migrations میں `begin/commit`، براؤزر فائلوں میں secrets نہ ہوں، دونوں adapter کاپیاں یکساں، فرنٹ اینڈ میں demo ڈیٹا نہ ہو، ہر `data-a` کا handler ہو، CSP موجود، inline handlers نہیں، supabase-js ایک ہی pinned ورژن، Edge Functions کا CORS/`verify_jwt` معاہدہ۔
- `tests/*.test.mjs`: معماری کے معاہدے، login-freshness منطق (`amr`/`last_sign_in_at`)۔
- `tests/e2e/frontend.e2e.mjs`: مہمان پڑھائی، XSS کی بے اثری، OTP لاگ اِن + onboarding، optimistic لائک/سیو/فالو اور rollback، تبصرے (جوابات)، composer (مسودہ، اشاعت، ترمیم، آف لائن)، پروفائل ایڈیٹر + ادائیگی کے طریقے، ڈونیٹ + دعوے + تاریخ، اطلاعات، تلاش، بلاک/ان بلاک، سیٹنگز/مدد/ٹکٹ/ٹیم/بیج/پلیٹ فارم/حذفِ اکاؤنٹ، حالیہ لاگ اِن کی خرابی، فیڈ کی خرابی + دوبارہ کوشش، نظم کی ترتیب، قاری کی ترجیحات، a11y۔
- `tests/e2e/admin.e2e.mjs`: کردار کے مطابق مینو، فلٹر، صفحہ بندی، ہر لکھائی کا عین payload (`reviewed_by` نہیں)، XSS، اکاؤنٹس ایڈیٹر، کردار تفویض، push، idle logout۔

> یہ e2e ٹیسٹ **in-memory mock** کے خلاف ہیں، حقیقی Supabase کے خلاف نہیں۔

## B. ڈیٹابیس ٹیسٹ (119)

```bash
cd hum-likhari-backend && supabase start && supabase test db
```
فائلیں: `database_schema.test.sql` (36)، `hardening.test.sql` (55)، `operations.test.sql` (28)۔ ہم نے انہیں حقیقی PostgreSQL 16 پر Supabase stub اسکیما + سادہ pgTAP stand-in کے ساتھ چلایا؛ اصل `supabase test db` (pg_prove، حقیقی `auth`/`storage` اسکیمے) پر دوبارہ چلانا لازمی ہے۔

## C. دستی — staging پر (دو عام اکاؤنٹس A، B اور ایک staff)

1. **Auth**: Google لاگ اِن؛ فون OTP (پاکستانی اور بین الاقوامی نمبر)؛ لاگ آؤٹ؛ ری لوڈ پر سیشن؛ onboarding (دلچسپیاں، سروے، چھوڑنا)۔
2. **پڑھنا/لکھنا**: فیڈ کے ٹیب، زمرے، تلاش (اردو)، مضمون؛ A شائع کرے، B دیکھے؛ مسودہ صرف A کو دکھے؛ کور تصویر؛ ترمیم؛ حذف۔
3. **سماجی**: لائک/سیو/فالو (دو آلات پر شمار درست)؛ تبصرہ اور جواب؛ بلاک کے بعد مواد غائب؛ رپورٹ۔
4. **ادائیگی کی معلومات**: A اپنا جاز کیش/بینک/QR محفوظ کرے، صرف "عوامی" کرنے پر B کو دکھے؛ B "بھیجنے کا طریقہ" دیکھ کر دعویٰ درج کرے؛ A وصولی کی تصدیق/منسوخی کرے؛ پلیٹ فارم معاونت کے اکاؤنٹس admin کے درج کردہ ہی دکھیں۔
5. **مدد/درخواستیں**: ٹکٹ + ملحقہ فائل؛ staff جواب → اطلاع؛ ٹیم/بیج درخواست → حالت کی اطلاع۔
6. **Staff**: رپورٹ پر مواد چھپانا → مصنف کو اطلاع؛ کردار تفویض/واپسی؛ audit میں اندراج؛ moderator کو admin سیکشن نہ دکھیں۔
7. **Push**: آلہ رجسٹر؛ لائک پر قطار بنے؛ شیڈیولر بھیجے؛ غلط ٹوکن بند ہو جائے۔
8. **حذفِ اکاؤنٹ** (ڈسپوزیبل اکاؤنٹ): حالیہ لاگ اِن کے بغیر انکار؛ `DELETE` لکھنے پر حذف؛ Storage فائلیں غائب۔

## D. لازمی منفی/حفاظتی ٹیسٹ

- مہمان: دوسروں کے مسودے، اطلاعات، لائکس، بک مارکس، feedback، QR/نجی منسلکات، ٹیم درخواستیں **نہ** دیکھ سکے۔
- صارف: دوسرے کی پوسٹ/پروفائل/اطلاع میں ترمیم نہیں؛ اپنی `like_count`/`published_at` نہیں بنا سکتا؛ ہٹائی گئی پوسٹ دوبارہ شائع نہیں کر سکتا؛ معطل ہو کر خود کو فعال نہیں کر سکتا۔
- Moderator: دوسرے کی تحریر کا متن نہیں بدل سکتا، صرف `status`؛ admin کردار نہیں دے سکتا؛ کسی تبصرے کو چھپانے کے بعد مصنف اسے واپس نہیں لا سکتا۔
- Support agent: posts/comments نہیں چھپا سکتا؛ بیج جاری نہیں کر سکتا؛ پلیٹ فارم معاونت `confirmed` نہیں کر سکتا۔
- `reviewed_by`/`reviewed_at` کلائنٹ کے بھیجے سے نہ بدلیں۔
- Push ٹوکن دوسرے صارف سے نہ پڑھا جائے؛ `push-dispatch` غیر admin اور غلط/چھوٹے secret پر 401/403 دے۔
- FCM service account یا service key براؤزر فائلوں/Git میں نہ ہو۔
- حذفِ اکاؤنٹ صرف حالیہ لاگ اِن + صریح `DELETE` سے ہو۔
