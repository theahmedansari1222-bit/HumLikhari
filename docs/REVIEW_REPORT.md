# ہم لکھاری — جائزہ اور حتمی رپورٹ (v1.0.0-rc.1)

یہ رپورٹ آپ کی درخواست کا جواب ہے: *ڈیزائن کے حساب سے فائلوں کا جائزہ؛ جو کوڈ میں ہے اور ڈیزائن میں نہیں وہ ڈیزائن میں شامل کرنا؛ کوڈ کی ترتیب اور لاجک درست کرنا (جہاں سب ٹھیک ہو وہاں دوبارہ نہ لکھنا)؛ پروڈکشن کے لیے تیار کوڈ کی زپ فائلیں؛ حتمی رپورٹ۔*

**ایک جملے میں:** کوڈ کو شروع سے دوبارہ نہیں لکھا گیا۔ ایپ کی شکل، اسکرینیں اور ڈیٹابیس کا بنیادی ڈھانچہ برقرار رکھا گیا؛ فرنٹ اینڈ کو ڈیمو ڈیٹا کی جگہ حقیقی بیک اینڈ سے جوڑا گیا، بیک اینڈ اور Edge Functions کی 10+ خامیاں دور کی گئیں، admin پینل مکمل کیا گیا، اور ڈیزائن میں وہ سب شامل کیا گیا جو کوڈ میں تھا مگر ڈیزائن میں نہیں تھا۔ **لیکن حقیقی Supabase، Google/SMS لاگ اِن اور push پر کچھ بھی آزمایا نہیں گیا (حصہ 6 دیکھیں) — اس لیے پہلے staging پر چلائیں، براہِ راست پروڈکشن پر نہیں۔**

## 1. ڈیزائن بمقابلہ کوڈ — موازنے کا نتیجہ

- **اسکرینیں:** کوڈ کی تمام 27 اسکرینیں اب ڈیزائن میں موجود ہیں۔ اصل ڈیزائن میں 20 پہلے سے تھیں؛ 7 (`survey`، `team`، `badges`، `platform`، `blocked`، `ticket`، `suspended`) کوڈ میں تھیں مگر ڈیزائن میں نہیں، اور وہ شامل کر دی گئیں۔ مدد، تعاون کی تاریخ، سیٹنگز، میری پسند اور او ٹی پی کی موجودہ اسکرینوں میں بھی کوڈ کے مطابق اضافے کیے گئے۔ صرف **"حالتیں"** اسکرین ڈیزائن میں اضافی ہے (لوڈنگ/خرابی/خالی حالتیں دکھانے کے لیے؛ کوڈ میں یہ ہر اسکرین کے اندر ہیں)۔
- **شیٹس:** سائن اِن ضروری، رپورٹ، بلاک، مواد ہٹایا گیا، لکھاری کا مزید مینو، اکاؤنٹ ڈیلیٹ (DELETE لکھ کر)، تعاون (اپنی رقم) — ڈیزائن میں شامل / درست کی گئیں۔
- **اصل ڈیزائن کا کوئی رویہ ہٹایا نہیں گیا**؛ ڈیمو ڈیٹا بھی وہی ہے۔ نئی اسکرینوں تک پہنچنے کے لیے فون فریم کے نیچے **"کوڈ میں شامل اضافی اسکرینیں"** کی پٹی ہے (480px سے چھوٹی اسکرین پر چھپی رہتی ہے)۔

## 2. کوڈ میں درست کیا گیا — بیک اینڈ (ڈیٹابیس)

نئی migration `20261113000000_security_hardening_and_app_support.sql` (forward-only؛ پرانی migrations میں ترمیم نہیں کی گئی)۔ `hardening.test.sql` کا ہر منظرنامہ پہلے اصل (v0.2.0) اسکیما پر حملے کے طور پر دہرایا گیا، پھر ٹھیک کیا گیا؛ ٹیسٹ اب ہر حل کی حفاظت کرتے ہیں (مثلاً F8: like/unlike/like پر ایک ہی اطلاع)۔

| # | خامی | حل |
|---|---|---|
| F1 | مصنف وہ تحریر دوبارہ شائع کر سکتا تھا جو موڈریٹر نے ہٹائی تھی | مصنف کی پالیسیاں `removed` کو خارج کرتی ہیں |
| F2 | INSERT میں جعلی `like_count`/`comment_count`/`published_at` | INSERT پر صریح column `GRANT` |
| F3 | معطل صارف خود `is_active = true` کر سکتا تھا | `profiles_guard_update` trigger |
| F4 | موڈریٹر کسی اور کی تحریر/پروفائل کا متن بدل سکتا تھا | guard triggers: غیر مصنف صرف `status` بدلے |
| F5 | تبصرے کا مصنف موڈریٹر کا چھپایا ہوا تبصرہ دوبارہ دکھا سکتا تھا | comment guard trigger |
| F6 | ایک صارف کا رجسٹر شدہ push ڈیوائس دوسرا صارف استعمال نہیں کر سکتا تھا | `register_push_device` RPC |
| F7 | کوئی بھی اسٹاف `reviewed_by/at` جعلی لکھ سکتا تھا | `stamp_review` trigger ڈیٹابیس خود لگاتا ہے |
| F8 | لائک/ان لائک اور فالو/ان فالو لوپ سے اطلاعات کی بھرمار | de-duplicating notification triggers |
| F9 | ہینڈل کی race سے signup ناکام ہو سکتا تھا | signup trigger ٹکراؤ پر abort نہیں کرتا |
| F10 | فیڈ/تلاش پوری تحریر (100KB تک فی قطار) لوٹاتی تھی | `post_feed_cards` view (400 حروف کا اقتباس) |

نیا: `search_posts`، `following_feed`، `saved_posts`، `profile_stats`، `unregister_push_device`، `acquisition_source_counts` (صرف مجموعی گنتی)، `platform_donation_accounts`، `notifications.ticket_id` اور `content_removed`، ہر لکھاری کے لیے ہر طریقے کا ایک ہی تعاون اختیار۔

## 3. کوڈ میں درست کیا گیا — Edge Functions

- **CORS:** مشترکہ سخت helper؛ صرف صریح origins کی فہرست (`HUM_LIKHARI_ALLOWED_ORIGIN`)، کوئی `*` نہیں۔
- **`delete-account`:** پرانی جانچ `auth_time` پر منحصر تھی، جو Supabase ٹوکن میں ہوتا ہی نہیں تھا — یعنی جانچ کبھی پاس نہیں ہو سکتی تھی۔ اب تازگی `amr[].timestamp` / `last_sign_in_at` سے (15 منٹ) نکالی جاتی ہے۔
- **`push-dispatch`:** دوبارہ لکھا گیا۔ `verify_jwt=false` مگر کوڈ میں اجازت: admin سیشن **یا** `x-dispatch-secret` (≥24 حروف، constant-time موازنہ)؛ قطار کی lease سے دوہری ترسیل نہیں؛ ناکامی پر back-off دوبارہ کوشش؛ مردہ ٹوکن غیر فعال؛ lock-screen پر عمومی متن۔
- **`manage-user-role`:** ہینڈل یا UUID سے کردار؛ آپ اپنا admin کردار خود واپس نہیں لے سکتے؛ ہر تبدیلی audit میں۔

## 4. کوڈ میں درست کیا گیا — فرنٹ اینڈ اور admin

**فرنٹ اینڈ** (شکل وہی، ڈیٹا کا راستہ بدلا): ڈیمو arrays ختم؛ ہر اسکرین `HLBackend` (Supabase adapter v2) سے پڑھتی/لکھتی ہے؛ لائک/محفوظ/فالو optimistic ہیں اور ناکامی پر واپس پلٹتے ہیں؛ لوڈنگ/خالی/خرابی/آف لائن حالتیں؛ ہر لکھنے والے بٹن پر busy-lock؛ ہر صارفی متن خودکار escape (`h\`\``)؛ CSP meta؛ placeholder کنفیگ پر setup اسکرین؛ آف لائن میں تحریر مقامی بفر میں محفوظ؛ supabase-js کا ایک ہی pinned ورژن (2.119.0)۔

اس آخری مرحلے میں ملی ایک اور خامی: **ٹکٹ کے جواب کا خانہ** وہ حصہ تھا جو تھریڈ لوڈ ہونے پر دوبارہ بنتا ہے، اس لیے لکھتے وقت دیر سے آنے والا لوڈ فوکس چھین سکتا تھا (ایک ٹیسٹ میں ایک بار فیل ہوا)۔ اب جواب کا خانہ اس حصے سے باہر ہے (جیسے تبصروں میں)۔ لکھا ہوا متن پہلے بھی نہیں مٹتا تھا (state میں محفوظ)، مگر کرسر چلا جاتا تھا۔

**admin پینل:** معاونت کے اکاؤنٹس کا ایڈیٹر، صارفین کی تلاش (PostgREST فلٹر sanitise)، ہینڈل سے کردار تفویض، ٹکٹ کی پوری گفتگو (عوامی جواب بمقابلہ اندرونی نوٹ)، 50 اندراج فی صفحہ، حالت کے فلٹر، مجموعی acquisition RPC، client سے review stamps نہیں بھیجتا، پڑھنے کے قابل خرابی کے پیغام، CSP، 30 منٹ idle پر سائن آؤٹ، ٹوکن refresh پر صفحہ reload نہیں۔ کرداروں کا میٹرکس `admin/README.md` میں۔

**ٹولنگ:** `scripts/validate.mjs` (adapter کی دونوں نقلیں یکساں، ڈیمو ڈیٹا نہیں، ہر `data-a` کا handler موجود، CSP موجود، ایک pinned supabase-js، CORS/`verify_jwt` معاہدے، کنفیگ فائلوں میں حقیقی keys نہیں)، GitHub Actions workflow۔

## 6. جو ابھی تصدیق شدہ نہیں — ایمانداری سے

یہ فہرست اس لیے ہے کہ "ٹیسٹ پاس" کو "پروڈکشن میں ٹھیک" نہ سمجھ لیا جائے۔

1. **حقیقی Supabase پروجیکٹ:** `supabase-adapter.js` کے PostgREST embeds اور فلٹرز کا نحو، Auth، Storage، publishable key کا رویہ — سب صرف mock کے خلاف چلے ہیں۔ یہ سب سے بڑا خطرہ ہے؛ `integration/smoke-test.html` staging پر پہلی چیز ہونی چاہیے۔
2. **حقیقی pgTAP اور Supabase اسکیما:** میری stub اور stand-in اصل سے مختلف ہو سکتی ہیں (خصوصاً `auth` اسکیما اور grants)۔ staging پر `supabase test db` لازماً چلائیں۔
3. **Google OAuth اور SMS OTP:** فراہم کنندہ کی ترتیب، redirect URLs، رسائی کی منظوری — کچھ نہیں آزمایا۔
4. **Firebase/FCM اور `push-dispatch`:** Deno دستیاب نہیں تھا؛ صرف TypeScript syntax اور تازگی کی منطق (Node سے) جانچی گئی۔ pg_cron + pg_net + vault شیڈیولر اور gateway کا `apikey` header بھی نہیں آزمایا۔
5. **supabase-js CDN:** ورژن pinned ہے مگر SRI hash نہیں لگایا (نیٹ ورک نہیں تھا)؛ پروڈکشن میں اپنے ڈومین سے سرو کریں یا hash لگائیں (`docs/DEPLOYMENT.md`)۔
6. **قانونی متن:** شرائط و ضوابط اور پرائیویسی پالیسی عبوری ہیں۔ وکیل سے بدلوائیں۔
7. **ادائیگی:** ایپ رقم منتقل نہیں کرتی؛ تعاون P2P ہے اور "میں نے بھیج دیا" صرف بھیجنے والے کا دعویٰ ہے۔ پلیٹ فارم معاونت دستی ریکارڈ ہے۔ ایپ اسٹور/پلے اسٹور کی ادائیگی پالیسیوں کا جائزہ باقی ہے۔
8. **لوڈ ٹیسٹ، penetration ٹیسٹ، اصل فونز/براؤزرز پر ٹیسٹ:** نہیں ہوئے۔
9. **چھوٹا مشاہدہ:** پروفائل ایڈٹ میں ادائیگی کا حصہ بھی جزوی re-render سے بنتا ہے؛ لوڈ مکمل ہونے کے بعد یہ ٹائپنگ میں دخل نہیں دیتا، مگر اگر مستقبل میں وہاں اور async کام جوڑیں تو ٹکٹ والا طریقہ (خانہ باہر رکھنا) اپنائیں۔
10. **ڈیزائن پریویو:** نمونہ ڈیٹا اور in-memory ہے؛ admin پریویو میں تبدیلیاں صفحہ reload پر مٹ جاتی ہیں۔
